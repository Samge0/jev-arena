Match Protocol

对局协议：公平性是设计出来的

每步对三引擎发送逐字节相同的请求，遵循 TypeSafe 官方文档与 NanoJev 作者实践。

RULE 01

逐字节相同题面

同一 (game, seed) 下三引擎看到完全相同的 state 文本与选项描述——对局协议即公平性保证。Tetris 死亡规则 = 落点越出顶边。

RULE 02

选项带真实后果数据

每个落点/方向附消行数、洞数变化、高度和/起伏度（Dellacherie 特征）。1024 选项必须携带真实合并后果——纯方向词会让所有模型原地打转。这是措辞工程，不是模型能力问题。

RULE 03

策略层级指令 + fan-out

Tetris「①消行②防洞③列低且均匀」；1024「①合并分②大合并③空格」。choice + noul 风险门一次调用并行（官方 12x 便宜 / 10x 快）。

RULE 04

TypeSafe 契约校验

答案规范化到契约：probabilities 键完备、归一、choice=argmax。不合规即判负，不给模型「口胡」空间。
